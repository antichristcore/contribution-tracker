# Git Project Management — Contribution Tracker

Telegram Mini App: доска задач, в которой по каждой задаче видно, **какими коммитами** она делалась. Тимлид студенческой команды видит реальный вклад участников и узнаёт о провисающей задаче до защиты, а не на ней.

## Как это работает

Задача получает номер. Участник упоминает его в сообщении коммита:

```
git commit -m "поправил валидацию #42"        # коммит привяжется к задаче 42, статус -> «в работе»
```

Синк тянет коммиты через GitHub REST API, находит `#номер` в сообщении и связывает коммит с задачей. Если номер забыли — в карточке задачи есть ручная привязка из списка «ничейных» коммитов.

Коммит задачу **не закрывает** — только привязывается и переводит её в «в работе». Ключевых слов вроде `fixes` в разборе нет намеренно: люди пишут «fix #42» в смысле «работаю над этим», и задача закрывалась на первом же коммите. Готовой её отмечает человек — галочкой на доске или кнопкой в карточке.

## Что видит тимлид

- **Задачи** — доска по статусам, у каждой карточки число связанных коммитов и счётчик «N дней без изменений».
- **Карточка задачи** — список коммитов с автором, датой, размером диффа и ссылкой на GitHub; история статусов.
- **Команда** — вклад каждого участника, пороги (жёлтый/красный), календарь коммитов и экран «Динамика команды».

Система показывает факты и не делает выводов о человеке — интерпретация за тимлидом.

## Формула вклада

Балл — целое от 0 до 100, ~50 это обычный рабочий уровень.

| Компонента | До | Как считается |
|---|---|---|
| Задачи в срок | +40 | доля закрытых до дедлайна среди задач, по которым срок уже наступил |
| Код | +35 | строк за 7 дней относительно медианы; медиана даёт половину веса, 2× медианы — весь |
| Ритм | +15 | дней с коммитами за 14; семи дней хватает на полный вес |
| Ревью | +10 | комментарии в чужих PR относительно медианы |
| Застой | −20 | растёт линейно до потолка на 7 днях без изменений по задаче |

Границы, без которых формула врёт:

- **компонента без данных исключается, а не обнуляется**, и её вес пропорционально уходит остальным. Команда без пул-реквестов иначе теряет вес ревью поголовно, а человек без назначенных задач — вес задач;
- срок сравнивается **по дню**: дедлайн почти всегда стоит на полночь, и задача, сданная в тот же день днём, считалась просроченной;
- задача без дедлайна не попадает в долю ни числителем, ни знаменателем — срок не проставил тимлид;
- один коммит засчитывается не больше чем в 1000 строк — иначе сгенерированный файл делает автора лучшим в команде;
- нормализованное значение обрезается на 2× медианы, чтобы одна аномалия не ломала шкалу;
- если в роли меньше двух человек с данными, сравнение идёт по всей команде, и интерфейс об этом прямо пишет;
- нет данных — это `None`, а не ноль.

В приложении есть экран «Как считается вклад» и разбор балла по слагаемым в карточке участника — оба рендерятся из тех же констант, что и расчёт.

## Стек

FastAPI + SQLAlchemy + SQLite · aiogram 3 (бот в том же процессе) · React 19 + Vite + Tailwind · APScheduler.

## Запуск

```bash
python -m venv .venv && .venv\Scripts\pip install -r requirements-dev.txt
cp .env.example .env          # заполнить BOT_TOKEN и MINI_APP_URL
cd frontend && npm install && npm run build && cd ..
.\scripts\start_server.ps1    # сервер + бот на :8000
```

Mini App требует публичный HTTPS-адрес — для разработки подойдёт туннель, его адрес кладётся в `MINI_APP_URL`.

**Демо без интернета**:

```powershell
.\.venv\Scripts\python scripts\seed_synthetic_demo.py   # 8 участников, 21 день истории
.\scripts\demo_local.ps1                                # http://localhost:8001/?as=1
```

Разовый переход на шкалу 0..100 (стирает историю старой шкалы и считает заново):

```powershell
.\.venv\Scripts\python scripts\migrate_score_scale.py
```

## Тесты

```bash
.venv\Scripts\python -m pytest
```

Покрыты формула вклада, пороги и привязка коммитов к задачам — то есть всё, что решает, получит ли живой человек уведомление.

## Данные

Собираются только объективные метрики активности: коммиты, размер диффа, задачи, ревью, дата последней активности, роль. Ничего чувствительного. Наружу данные не уходят.

Вход в проект требует GitHub username — он проверяется через GitHub API. Без привязки коммиты участника остаются ничьими, вклад не считается, и человек висит в команде как «нет данных», не понимая почему.
