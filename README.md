# Git Project Management — Contribution Tracker

Telegram Mini App: доска задач, в которой по каждой задаче видно, **какими коммитами** она делалась. Тимлид студенческой команды видит реальный вклад участников и узнаёт о провисающей задаче до защиты, а не на ней.

## Как это работает

При создании задача получает номер. Участник упоминает его в сообщении коммита:

```
git commit -m "поправил валидацию #42"        # коммит привяжется к задаче 42, статус -> «в работе»
```

Синхронизация тянет коммиты через GitHub REST API, находит `#номер` в сообщении и связывает коммит с задачей. Если номер забыли, в карточке задачи есть ручная привязка из списка «ничейных» коммитов.

Коммит задачу **не закрывает**, а только привязывается к ней и переводит её в «в работе». Ключевых слов вроде `fixes` в разборе нет намеренно: люди пишут «fix #42» в смысле «работаю над этим», и задача закрывалась на первом же коммите. Готовой её отмечает человек, галочкой на доске или кнопкой в карточке.

## Что видит тимлид

- **Задачи** — доска по статусам («К выполнению», «В работе», «Готово»), у каждой карточки число связанных коммитов и счётчик «N дней без изменений».
- **Карточка задачи** — список коммитов с автором, датой, размером диффа и ссылкой на GitHub; история статусов.
- **Команда** — вклад каждого участника, пороги (жёлтый/красный), календарь коммитов и экран «Динамика команды».
- **Мой прогресс** (это видит участник) — своя карточка с баллом. Чужие баллы участникам не показываются намеренно, чтобы инструмент не стал источником конфликта в команде.

Приложение показывает факты и не делает выводов о человеке. Интерпретация остаётся за тимлидом.

## Формула вклада

Балл — целое от 0 до 100, ~50 это обычный рабочий уровень.

| Компонента | Макс. | Как считается |
|---|---|---|
| Задачи в срок | +40 | доля закрытых до дедлайна среди задач, по которым срок уже наступил |
| Код | +35 | строк за 7 дней относительно медианы; медиана даёт половину веса, 2× медианы — весь |
| Ритм | +15 | дней с коммитами за 14; семи дней хватает на полный вес |
| Ревью | +10 | комментарии в чужих PR относительно медианы |
| Задачи без движения | −20 | растёт линейно до потолка на 7 днях без изменений по задаче |

Границы, без которых формула врёт:

- компонента без данных исключается, а не обнуляется, и её вес пропорционально уходит остальным. Иначе команда без пул-реквестов теряет вес ревью поголовно, а человек без назначенных задач теряет вес задач;
- срок сравнивается по дню: дедлайн почти всегда стоит на полночь, и задача, сданная в тот же день днём, считалась просроченной;
- задача без дедлайна не попадает в долю ни числителем, ни знаменателем, потому что срок не проставил тимлид;
- один коммит засчитывается не больше чем в 1000 строк, иначе сгенерированный файл делает автора лучшим в команде;
- нормализованное значение обрезается на 2× медианы, чтобы одна аномалия не ломала шкалу;
- если в роли меньше двух человек с данными, сравнение идёт по всей команде, и интерфейс об этом прямо пишет;
- нет данных — это `None`, а не ноль.

В приложении есть экран «Как считается вклад» и разбор балла по слагаемым в карточке участника. Оба рендерятся из тех же констант, что и расчёт.

## Пороги

**Жёлтый** (мягкое личное напоминание участнику):

- вклад ниже медианы команды на 40%+ в течение 5 дней подряд, либо
- 4+ дня без единой активности при наличии незакрытых задач

**Красный** (уведомление тимлиду с именем, задачей и числом дней):

- жёлтый порог держится ещё 3+ дня, либо
- конкретная задача застряла на 7+ дней без изменений

## Стек

FastAPI + SQLAlchemy + SQLite · aiogram 3 · React 19 + Vite + Tailwind · APScheduler.

## Запуск

```bash
python -m venv .venv && .venv\Scripts\pip install -r requirements-dev.txt
cp .env.example .env          # заполнить BOT_TOKEN и MINI_APP_URL
cd frontend && npm install && npm run build && cd ..
.\scripts\start_server.ps1    # сервер + бот на :8000
```

Mini App требует публичный HTTPS-адрес. Для разработки подойдёт туннель, его адрес впиши в `MINI_APP_URL`.

## Тесты

```bash
.venv\Scripts\python -m pytest
```

Тесты покрывают формулу вклада, пороги и привязку коммитов к задачам, то есть всё, что решает, получит ли живой человек уведомление.

## Данные

Приложение собирает только объективные метрики активности: коммиты, размер диффа, задачи, ревью, дату последней активности, роль. Ничего чувствительного. Наружу данные не уходят.

Вход в проект требует GitHub username, он проверяется через GitHub API. Без привязки коммиты участника остаются ничьими, вклад не считается, и человек висит в команде как «нет данных», не понимая почему.
