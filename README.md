# Git Project Management — Contribution Tracker

Telegram Mini App: доска задач, в которой по каждой задаче видно, **какими коммитами** она делалась. Тимлид студенческой команды видит реальный вклад участников и узнаёт о провисающей задаче до защиты, а не на ней.

## Как это работает

Задача получает номер. Участник упоминает его в сообщении коммита:

```
git commit -m "поправил валидацию #42"        # коммит привяжется к задаче 42, статус -> «в работе»
git commit -m "готово, fixes #42"             # задача закроется
```

Синк тянет коммиты через GitHub REST API, находит `#id` в сообщении и связывает коммит с задачей. Если номер забыли — в карточке задачи есть ручная привязка из списка «ничейных» коммитов.

Закрывает задачу только ключевое слово **непосредственно перед** ссылкой (`fixes #42`), как в GitHub. Обычное «Fix login bug #42» просто привязывает коммит.

## Что видит тимлид

- **Задачи** — доска по статусам, у каждой карточки число связанных коммитов и счётчик «N дней без изменений».
- **Карточка задачи** — список коммитов с автором, датой, размером диффа и ссылкой на GitHub; история статусов.
- **Команда** — вклад каждого участника, пороги (жёлтый/красный) и экран «До / После».

Система показывает факты и не делает выводов о человеке — интерпретация за тимлидом.

## Формула вклада

```
score = 0.35 × norm(строк изменено за 7д)
      + 0.35 × (задач сдано в срок / назначено)
      + 0.15 × norm(ревью чужих PR)
      − 0.15 × штраф(дней застоя)
```

Нормализация — относительно медианы, по возможности внутри роли (дизайнера сравниваем с дизайнерами). Границы, которые стоит знать:

- один коммит засчитывается не больше чем в 1000 строк — иначе любой большой коммит делает автора лучшим в команде;
- нормализованное значение обрезается на 2× медианы, чтобы одна аномалия не ломала шкалу;
- если задач не назначено, компонента задач **исключается**, а не считается нулём — иначе новичок теряет 35% ни за что;
- если в роли меньше двух человек с данными, сравнение идёт по всей команде, и интерфейс об этом прямо пишет.

## Стек

FastAPI + SQLAlchemy + SQLite · aiogram 3 (бот в том же процессе) · React 19 + Vite + Tailwind · APScheduler.

## Запуск

```bash
python -m venv .venv && .venv\Scripts\pip install -r requirements-dev.txt
cp .env.example .env          # заполнить BOT_TOKEN и MINI_APP_URL
cd frontend && npm install && npm run build && cd ..
.\scripts\start_server.ps1    # сервер + бот на :8000
```

Mini App требует публичный HTTPS-адрес — для разработки подойдёт туннель, его адрес кладётся в `MINI_APP_URL`.

**Демо без интернета**:

```powershell
.\.venv\Scripts\python scripts\seed_synthetic_demo.py   # 8 участников, 21 день истории
.\scripts\demo_local.ps1                                # http://localhost:8001/?as=1
```

## Тесты

```bash
.venv\Scripts\python -m pytest
```

Покрыты формула вклада, пороги и привязка коммитов к задачам — то есть всё, что решает, получит ли живой человек уведомление.

## Данные

Собираются только объективные метрики активности: коммиты, размер диффа, задачи, ревью, дата последней активности, роль. Ничего чувствительного. Наружу данные не уходят.
