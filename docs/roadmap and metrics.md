### Этап 0. Предпроектный анализ

- Проведён опрос 30 потенциальных пользователей (тимлидов и разработчиков).
    
- Собраны боли: нехватка единого окна для задач + коммитов, сложность ручного связывания кода с заданиями.
    
- Сформулированы базовые требования:
    
    - Привязка задачи → коммит → ссылка в GitHub.
        
    - Отображение активности команды в графиках.
        
    - Интеграция с Telegram (мини-приложение).
### Этап 1. Базовый функционал (MVP) 

- Реализовать авторизацию через Telegram (получение user_id, аватар, имя).
    
- Создать интерфейс для тимлида:
    
    - Создание задачи (название, описание, дедлайн, назначенный сотрудник).
        
    - Список всех задач с фильтрацией по статусу (открыта / в работе / выполнена).
        
- Подключить GitHub OAuth для каждого пользователя (чтобы приложение могло читать коммиты).
    
- Реализовать механизм: сотрудник, выполнив задачу, пишет хэштег в коммите, чтобы приложение его увидело.
    
- Отображение в карточке задачи:
    
    - Ссылка на коммит (кликабельная, ведёт в GitHub).
        
    - Дата коммита, автор.
        
- Базовая страница «Активность команды»:
    
    - Список всех сотрудников с количеством выполненных задач за неделю. И графиком активности

- **Автоматическое связывание:**
    
    - Настроить webhook от GitHub на ваше приложение (или периодический опрос API).
        
    - При новом коммите парсить сообщение на наличие номера задачи (например, `#TASK-123`) и автоматически привязывать коммит к задаче.
        
    - Если номер не найден – отправлять уведомление сотруднику с просьбой указать задачу.
- Интеграция с Telegram Bot API – отправка уведомлений тимлиду о новых коммитах по его задачам и уведомлений об отставаний сотрудников.
- Личный кабинет сотрудника:
    
    - Он видит только свои задачи, свою статистику, график своей активности.
        
    - Может сравнить себя со средним по команде (без имён).
        
### Этап 2. Аналитика 

- **Расширенная статистика:**
    
    - График активности по каждому сотруднику за день/неделю/месяц (количество коммитов, добавленных/удалённых строк, время между коммитами).
        
    - Тепловая карта активности команды (часы пик, дни с максимальной нагрузкой).
        
    - Прогресс выполнения задач по спринтам (диаграмма Ганта или burn-down).
        
- **Рейтинг (на основе данных опроса + активность):**
    
    - Вычислять интегральный показатель:
        
        - Вес коммитов (по размеру, по сложности задачи).
            
        - Соблюдение дедлайнов.
            
        - Участие в код-ревью (если есть доступ к PR).
            
    - Отображать таблицу лидеров внутри команды (анонимно или с именами – на усмотрение тимлида).

### Этап 4. Масштабирование и интеграции – **постоянно**

- Добавление поддержки других Git-платформ (GitLab, Bitbucket) – если команда использует не только GitHub.
