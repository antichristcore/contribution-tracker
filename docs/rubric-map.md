# Карта критериев: кто чем закрывает баллы

Файл для тимлида. Разбирает критерии жюри по владельцам, чтобы не осталось
пунктов, за которые не отвечает никто.

## Главное, что видно из весов

| Критерий | Вес | Про что на самом деле |
|---|---|---|
| Проблема и пользователь | 1,8 | исследование, не код |
| Вклад четырёх направлений | 1,8 | артефакты + репетиция, не код |
| Что реально работает | 1,5 | код и стенд |
| Командность и самостоятельность | 1,5 | кто говорит и какие решения принимали |
| Прогресс и рост | 1,4 | история недели |
| Питч и подача | 1,2 | структура выступления |
| Ответы и честность | 0,8 | подготовка к вопросам |

**Кодом закрывается 1,5 балла из 10.** Остальные 8,5 — исследование, артефакты,
репетиция и честность. Продукт уже работает; дальше выигрыш даёт не новая фича,
а то, что вокруг него.

Веса дают максимум 100 баллов (оценка 0–10 × вес).

## Четыре звена: что говорит каждый

Критерий «вклад четырёх направлений» даёт 10 только если **каждый объясняет свой
артефакт и его связь с соседним**. Не «я делал бэкенд», а цепочка:

1. **БА:** «Тимлид узнаёт о проседании участника на предзащите. Вот N ответов
   на опрос, вот цифра. Сейчас он выясняет это руками, обходя людей в чате.»
2. **СА:** «Из этой боли получилось правило: вклад считается вот так, порог
   срабатывает вот на этих числах, и вот почему числа именно такие.»
3. **Разработка:** «Правило работает на реальных коммитах из GitHub API, а не на
   выдумке. Вот тесты, которые его держат.»
4. **Девопс:** «И это поднимается одной командой на любом ноутбуке, сбрасывается
   в известное состояние и не разваливается, когда GitHub отвечает ошибкой.»

Проговорить цепочку вслух до защиты минимум дважды. Пункт про «связь с соседним»
жюри проверяет вопросом «а зачем тебе то, что сделал он?» — ответ должен быть
готов.

## Пять гейтов между «8» и «10»

Это то, чего сейчас нет, а стоит оно дорого — по 1–2 балла в каждом критерии.

**1. «Воспроизводится дважды» + «обработка отказа»** (критерий 2)
Восьмёрка — сценарий проходит один раз. Десятка — проходит дважды подряд и
показано, что бывает при сбое. Владелец: девопс, задачи P0-2 и P0-3.

**2. Артефакт у каждого + каждый его защищает словами** (критерий 3)
Сейчас в репозитории **один коммит от одного автора**. Если жюри посмотрит
историю — увидит, что работал один человек. Владелец: девопс, задача P1-5.

**3. Решение, принятое вопреки первоначальной идее** (критерий 4)
У команды такие решения уже есть, просто не записаны:
- отказались от вебхуков в пользу опроса по REST — вебхук на демо может не
  долететь, и это будет видно жюри;
- участник без назначенных задач сначала получал ноль за компоненту задач;
  поняли, что новичок теряет 35% ни за что, — компоненту стали исключать;
- один коммит перестали считать целиком: `package-lock.json` на 40 000 строк
  делал автора лучшим в команде, поставили потолок 1000 строк;
- отказались от рейтинга и ярлыков вида «плохой участник» — инструмент не
  должен становиться источником конфликта, показываем только факты.

Любое из этих — готовый ответ на «назовите решение вопреки первоначальной идее».
Записать в `docs/decisions.md`. Владелец: тимлид.

**4. «Что пришлось выбросить и почему это было правильно»** (критерий 5)
Кандидаты: вебхуки, интеграция с Trello/Jira, преподаватель как второй
пользователь, третий диагноз «отвлёкся». Выброшено не от лени, а ради того,
чтобы один сценарий прошёл целиком — так и говорить.

**5. Слабое место, названное раньше жюри** (критерий 7)
Назвать первыми:
- задачи синтетические, реальная интеграция только по коммитам;
- порог «40% ниже медианы» подобран на глаз, а не выведен из данных;
- третий диагноз из ТЗ не реализован — знаем, спека написана;
- на команде из одного человека медиана равна его же результату, сравнивать
  не с кем.
Владелец: все, свести в `docs/weak-spots.md`.
